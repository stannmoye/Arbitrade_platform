## Checkpoint 13 — Approved package-fee versions and delivery-only retry contract (documentation/CI scope)

- **Approved fee decision:** Fee policies are package-specific and append-only. The initial forward migration must create version 1 for every existing package by copying the current valid legacy global rate and rounding rule exactly; its reason/provenance identifies **migration baseline**. Missing, invalid, incomplete, or unsupported source data fails closed without a guessed default or partial baseline.
- Every new fee save appends a version. New allocations, if separately authorized in the future, snapshot package ID, fee rate, fee version, rounding rule, and effective time. Changes affect future allocations only. Historical trades, settlements, and ledger entries are never rewritten or recomputed using the latest settings. The existing administrator-confirmed credit/debit posting worker remains active and uses the saved settlement snapshot.
- **Hard safety boundary:** automatic trading/execution, result determination, and automatic customer-fund allocation remain hard-disabled. Informational delivery and its retries never cause financial activity.
- **Delivery policy:** `maxPendingDeliveries` counts only `queued`, `in_progress`, and `retry_wait`; dismissed and expired are terminal. `maxDeliveryAttempts=3` means attempts 1–3 total. The single shared Retry & Carry-Forward owner controls policy, maximum attempts, and delivery-specific intervals. No interval is guessed; until valid intervals are saved, use no-retry/fail-closed. Delivery retry is not trade-execution retry.
